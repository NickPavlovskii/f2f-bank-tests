## BUG-01 | После Logout кнопка «Назад» открывает закешированную главную

| | |
|---|---|
| **Приоритет** | Высокий |
| **Область** | Авторизация / безопасность (bfcache) |
| **Окружение** | Chromium, `http://localhost` |
| **Тест** | TC-LOGOUT-02 |

### Шаги
1. Войти в систему.
2. Открыть главную `/`.
3. Нажать Logout в шапке → оказались на `/login`.
4. Нажать Back в браузере.

### Фактически
URL становится `http://localhost/` — отображается закешированная авторизованная страница (bfcache).

### Ожидалось
Пользователь не должен видеть защищённый экран. Нужен редирект на `/login` либо пустой/гостевой UI без данных сессии.

### Риск
На банковском UI это выглядит как восстановление сессии после выхода. Даже если cookie уже очищен, кратковременный показ личного экрана недопустим.

### Заметка по коду
Logout на клиенте чистит cookie и `profile` локально, но **не вызывает** `POST/GET /api/auth/logout`. Страница не помечается как `Cache-Control: no-store` для bfcache.

## BUG-02 | Logout не обращается к API logout

| | |
|---|---|
| **Приоритет** | Высокий |
| **Область** | Авторизация |
| **Где** | `client/src/components/Header.vue` |

### Фактически
При выходе: `clearCookie('access_token')` + `router.push('/login')`. Запроса на сервер `/api/auth/logout` нет.

### Ожидалось
Сервер должен инвалидировать сессию/токен. Только клиентская очистка cookie недостаточна (другая вкладка, украденный JWT до истечения TTL и т.д.).

## BUG-03 | Email при логине чувствителен к регистру

| | |
|---|---|
| **Приоритет** | Средний |
| **Область** | Авторизация |
| **Тест** | TC-LOGIN-08 |

### Шаги
1. Зарегистрировать пользователя с email `user....@test.com`.
2. Войти с тем же адресом в другом регистре local-part (`USER....@test.com`) и верным паролем.

### Фактически
Snackbar `Login failed`, вход не выполняется.

### Ожидалось
Обычно email сравнивают case-insensitive (хотя бы local-part или весь адрес по политике продукта).

## BUG-04 | Email при логине не trim’ится

| | |
|---|---|
| **Приоритет** | Средний |
| **Область** | Авторизация |
| **Тест** | TC-LOGIN-07 |

### Шаги
1. Зарегистрировать пользователя.
2. На логине ввести email с пробелами по краям и верный пароль.

### Фактически
Либо браузерная валидация `type="email"` блокирует отправку, либо (если запрос уходит) вход не проходит — на фронте trim перед API нет.

### Ожидалось
Пробелы по краям email игнорируются (`trim`), пользователь входит успешно.

## BUG-05 | Поле Password на регистрации с битым `name`

| | |
|---|---|
| **Приоритет** | Низкий / Средний (качество разметки) |
| **Область** | Регистрация |
| **Где** | `RegisterView.vue` → `AppInput` password |

### Фактически
У password `name="Type your password"` (похоже, перепутан placeholder и name). Нормального `name="password"` нет.

### Ожидалось
`name="password"`, корректный `placeholder`. Это ломает автозаполнение и усложняет селекторы в тестах/a11y.
